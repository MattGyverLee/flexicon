--------------------------------------------------------------------------------
ON uow_refused=FP_ReadOnlyError (looks like a T010 miss; it is not)
--------------------------------------------------------------------------------
T010 requires UndoableOperation() on an attached view to raise
FP_TransactionError naming FromOpenProject. Probe C saw FP_ReadOnlyError with no
mention of the bridge, because this session is read-only and
_FLExUndoableOperation.__enter__ checks writeEnabled BEFORE the attached-view
branch.

That ordering is deliberate and documented in place
(flexicon/code/undoable_operation.py:86-107), and pinned by the named test
test_read_only_attached_view_reports_read_only_not_attached_view. The asymmetry
against SaveChanges (T011, where the attached-view check goes FIRST) is the
point: SaveChanges must refuse even a write-enabled view because the host owns
the save, whereas a read-only view cannot write by any route, and pointing such
a caller at Transaction() would be a wrong answer in the shape of a helpful one.

The write-enabled attached view -- where T010's message IS the right answer --
is covered by the CP2 unit suite, run alongside this probe:

    python -m pytest tests/test_from_open_project.py -q
    39 passed in 1.23s

The bridge is read-transparent: a module written in the SPEC 3d shape returns
byte-identical results to one using project.LexEntry directly, and does so
whether FromOpenProject short-circuits (MCP) or genuinely attaches (FlexTools).
The US2 lifecycle guards also hold against a live cache: CloseProject() is a
silent no-op that leaves the host's cache alive, and SaveChanges() refuses while
naming the bridge and without repeating the CloseProject() advice (R7).

why Invariant A discriminates on _attached_donor rather than on _undoable.

INCIDENTAL DEFECT FOUND AND FIXED (in the gate module, not in flexicon)
  The first draft of the gate module resolved its target with
  fx.Object(TARGET_SENSE_GUID). That returns the object at its base ICmObject
  type, and reading the gloss off it died with

      'ICmObject' object has no attribute 'Gloss'

  Senses reached via LexEntry.GetAllSenses() come back correctly typed, so the
  module now walks from the owning entry and needs no pythonnet cast. Worth
  noting for US4's docs: the portable module shape should navigate, not resolve
  a bare GUID, unless the caller is prepared to cast.
