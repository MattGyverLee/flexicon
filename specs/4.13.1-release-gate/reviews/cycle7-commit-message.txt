fix(api): affix inflection classes, withdrawn example media, dependent-clause rows

Three 4.13.1 release-gate P1s where the published surface rested on an LCM
field or element type that does not exist. Each implements the user's
option A (2026-11-02) and is a Principle VII cause-2 change: the surface
was wrong.

#830: InflectionClassesRC exists only on IMoAffixForm (MoAffixAllomorph and
MoAffixProcess); IMoStemAllomorph has no such field. The Allomorphs methods
GetInflectionClasses, AddInflectionClass and RemoveInflectionClass now cast
affix forms locally to IMoAffixForm and work on that collection. Add is
idempotent by HVO, with the existence check outside the transaction;
Remove matches by HVO and is a no-op if absent. On a stem allomorph Get
returns [] and Add/Remove raise FP_ParameterError naming
project.MSA.SetInflectionClass, because a stem's class lives on its MSA.
Any other class raises FP_ParameterError. The shared resolver is untouched.
MoAffixProcess is covered offline only; no live fixture contains one.

#831: ILexExampleSentence has no MediaFilesOS. Examples.AddMediaFile,
RemoveMediaFile and MoveMediaFile now emit a DeprecationWarning and raise
FP_ParameterError before any file copy, LCM access or transaction.
GetMediaFiles returns [] and GetMediaCount returns 0, both with a
DeprecationWarning. All five are removed in 5.0; purpose-built audio
methods are planned for 4.14.0 as additive API. The error message names the
audio writing-system route (SetExample on the audio writing system) as
observed in surveyed data. That route was not exercised in a sandbox,
because neither Target nor Sena 3 has an audio writing system.

#832: IConstChartClauseMarker.DependentClausesRS holds IConstChartRow, not
markers. AddDependentClause and InsertDependentClause take an
IConstChartRow or its HVO as the row argument, renamed row_or_hvo with the
positional order unchanged. Any other class, including a clause marker,
raises FP_ParameterError. Add is idempotent by HVO. GetDependentClauses
casts its elements to IConstChartRow. The methods write only
DependentClausesRS; FLEx also sets the row's ClauseType and the
Start/EndDependentClauseGroup flags, so a [WARN] is logged when the added
row is Normal (design rule 6). A FLEx-faithful helper is planned for
4.14.0. The FLExProject docstring example and
demos/demo_discourse_operations.py now pass a row.

BREAKING CHANGE: Principle VII cause 2, the surface was wrong.
Allomorph inflection classes (issue #830): GetInflectionClasses now returns the
real InflectionClassesRC list for affix allomorphs and affix processes,
where before it returned [] for every allomorph; stem allomorphs still
return []. AddInflectionClass and RemoveInflectionClass now work on affix
forms, where they used to raise FP_ParameterError. On stem allomorphs they
used to fail on the missing field and now raise FP_ParameterError naming
project.MSA.SetInflectionClass. Any other class raises FP_ParameterError.
Example media (issue #831): AddMediaFile, RemoveMediaFile and MoveMediaFile raise
FP_ParameterError on every call, before any file copy, write-enabled check
or transaction. Callers that caught FP_ReadOnlyError or
FP_NullParameterError from them now get FP_ParameterError first. Their old
return values are gone: AddMediaFile no longer returns an ICmFile and
MoveMediaFile no longer returns a bool. GetMediaFiles returns [] and
GetMediaCount returns 0. All five emit DeprecationWarning and are removed
in 5.0.
Dependent clauses (issue #832): the second argument of AddDependentClause and the
third of InsertDependentClause are renamed to row_or_hvo, so keyword
callers break, and must be an IConstChartRow or its HVO; a clause marker
raises FP_ParameterError. GetDependentClauses elements are now cast to
IConstChartRow. Adding a Normal row logs a warning.
None of these methods worked against the published surface. Migration:
docs/MIGRATION_GUIDE.md.
